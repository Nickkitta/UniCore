# Наполнение UniCore

Стартовый набор в `starter.json`: 12 пользователей, 4 сообщества, 16 событий
Имена, сообщества, мероприятия, цены и геометки вымышленные, это данные для разработки и показов
События создаются без фотографий, фотографии можно прикреплять при создании событий в приложении
Чужие пользовательские данные сидер не удаляет и не изменяет

## Первый запуск

1. Один раз выполнить миграцию `../migrations/202611120003_organizations.sql` после первых двух миграций
2. Скопировать `.env.seed.example` из корня проекта в `.env.seed.local`, если локальный файл ещё не создан
3. Указать адрес своего тестового проекта и secret key или старый service_role key в `SUPABASE_SEED_ADMIN_KEY`
4. Из корня проекта выполнить `npm run seed:preview`, затем `npm run seed`

Ключ берётся в Supabase → Project Settings → API Keys
Он используется только локальным Node-скриптом, имя переменной не должно начинаться с `EXPO_PUBLIC_`
`.env.seed.local` и каталог `.local/` исключены из Git
Сидер использует Admin Auth API с `email_confirm: true` — письма не отправляются
Почта тестовых аккаунтов использует зарезервированный домен `example.com`

После запуска учётные данные созданных пользователей находятся в `.local/unicore-seed/<проект>.<набор>.accounts.json`
У каждого пользователя свой случайный пароль, в консоль он не выводится
Запись сохраняется до создания аккаунта, чтобы восстановить запуск после сетевой ошибки
Статус `created` означает успешное создание аккаунта
Пароли уже существующих аккаунтов не сбрасываются, при потере локального файла их нужно менять отдельно через администрирование Auth

## Команды

```powershell
# Проверить состав и связи без сети и без ключа
npm run seed:preview

# Добавить недостающие записи
npm run seed

# Перенести даты только событий этого набора относительно сегодняшнего дня
npm run seed:refresh

# Использовать свою копию набора и базовую дату
npm run seed -- --file supabase/seeds/my-set.json --start-date 2026-12-01
```

Повторный запуск использует те же ID и добавляет только недостающие записи
Изменения текстов, профилей и оформления в существующих записях сохраняются
`seed:refresh` явно обновляет только даты событий текущего набора, цены и содержание не меняет
Дата рассчитывается в часовом поясе Волгограда, UTC+3
Если команда прервалась, её можно повторить — весь запуск не является одной транзакцией, уже созданные записи останутся

## Как изменить набор

Добавь запись в `users`, `organizations` или `events` с новым уникальным `key`
`owner` сообщества и `host` события ссылаются на ключ пользователя
`organization` события ссылается на ключ сообщества, организатор должен быть его владельцем
`daysFromStart` задаёт день после базовой даты, `time` — местное время
`priceRub: 0` означает бесплатное участие, координаты можно опустить
Ключи и `namespace` определяют постоянные ID — менять их для обновления существующей записи не следует
Новый `namespace` создаёт отдельный набор, при этом адреса пользователей тоже должны быть уникальными

Пользователи получают обычную роль `authenticated`, административные права им не назначаются
Привязать своё событие к чужому сообществу обычный пользователь не может
Сидер проверяет служебные метки и останавливается при конфликте ID с существующими данными
Создание самих сообществ пока выполняется через сидер или администрирование базы, отдельной формы управления сообществом в приложении нет
