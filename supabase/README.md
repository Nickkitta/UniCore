# UniCore backend

## Подключение

Приложение использует Supabase Auth и PostgreSQL через `apps/mobile/src/services/supabaseRepository.ts`
Параметры проекта находятся в локальном `apps/mobile/.env.local`, шаблон — `apps/mobile/.env.example`
Для облачной сборки APK те же публичные переменные нужно настроить в окружении Expo Build — локальный файл исключён из Git
В мобильном приложении используется только publishable key
Пароль базы и secret/service-role ключи в приложение не добавлять

1. Выполнить `migrations/202611120001_unicore.sql` целиком в SQL Editor один раз
2. Создать первый аккаунт в Authentication → Users → Add user → Create new user
3. Для закрытого теста можно включить Auto Confirm User при создании аккаунта администратором
4. Перезапустить `npm start` в корне репозитория после настройки `apps/mobile/.env.local` и войти по почте и паролю

Миграция создаёт только таблицы с префиксом `unicore_`, существующие данные других приложений не изменяет
Миграции хранятся в репозитории, последующие изменения оформлять новыми файлами
Исходную миграцию повторно не запускать

## События с фотографиями и настройкой оформления

После первой миграции один раз выполнить `migrations/202611120002_event_posts.sql`
Она добавляет тему профиля, целочисленную цену в рублях, необязательные координаты и массив путей фотографий
Новый клиент создаёт события через `unicore_create_event`, старый RPC оставлен для совместимости
Разделы афиши и приглашений объединены в ленту «События», прежние записи остаются видимыми

Фотографии выбираются через системный диалог, преобразуются в JPEG с длинной стороной до 1600 px и сохраняются в приватный bucket `unicore-events`
Лимит — пять изображений до 5 МБ каждое
Путь загрузки начинается с ID владельца, база проверяет владельца и существование объекта до публикации
Временные URL фотографий выдаются вошедшим пользователям на час
Неопубликованные фотографии доступны владельцу, опубликованные — участникам приложения
Удаление прикреплённого к событию файла напрямую из клиента запрещено
При неуспешной публикации клиент пытается удалить уже загруженные файлы, незавершённые загрузки после закрытия приложения потребуют отдельной периодической уборки

`EXPO_PUBLIC_YANDEX_MAPS_API_KEY` задаётся в `apps/mobile/.env.local` и окружении сборки
Ключ должен поддерживать JavaScript API Яндекс Карт
В браузере карта открывается в iframe, на Android — в WebView, точка выбирается нажатием
Доступ к геолокации устройства не запрашивается, адрес и точка независимы
Перед публикацией приложения проверить разрешённые домены и условия использования ключа в кабинете Яндекса

Платное участие — только обозначение цены и подтверждение записи
UniCore не принимает оплату, не хранит платёжные данные и не выдаёт оплаченные билеты
Тема хранится в `unicore_profiles.theme`, доступна только владельцу профиля и загружается при входе

## Регистрация без писем для закрытого тестирования

В Supabase открыть Authentication → Sign In / Providers, в общем блоке User Signups отключить Confirm email и сохранить настройки
Переключатель находится на основной странице провайдеров, а не внутри боковой панели Email
Это настройка облачного проекта, публичный ключ приложения не позволяет менять её
После отключения новая регистрация возвращает сессию, приложение сразу загружает профиль и открывает события
Изменять код или выполнять SQL-миграцию для этого не нужно
Владение почтовым адресом в этом режиме не проверяется, перед открытым запуском вернуть подтверждение и настроить SMTP
Фактическое состояние переключателя проверяется в Supabase, этот документ сам его не изменяет

## Регистрация с письмами

В интерфейсе есть регистрация, подтверждение почты и повторная отправка письма
Подтверждение само по себе не создаёт фиктивную клиентскую сессию — после перехода по ссылке пользователь входит по паролю

До открытой регистрации настроить свой SMTP в Authentication и доступный пользователям Site URL / Redirect URLs
Письмо должно возвращать пользователя на существующую страницу подтверждения, затем он может вернуться в приложение
Встроенный SMTP Supabase ограничен адресами команды проекта и не предназначен для обычной регистрации пользователей
Для первых закрытых проверок подходят аккаунты, созданные администратором, без рассылки приглашений
Восстановление пароля и удаление аккаунта через мобильный интерфейс пока не реализованы

Официальные инструкции:
- https://supabase.com/docs/guides/auth/auth-smtp
- https://supabase.com/docs/guides/auth/redirect-urls
- https://supabase.com/docs/guides/auth/quickstarts/react-native

## Данные и доступ

- `unicore_profiles` — собственный профиль, email хранится в Auth и не публикуется другим пользователям
- `unicore_activities` — общая афиша и приглашения
- `unicore_participants` — участие с уникальной парой встреча/пользователь
- `unicore_saved` — личные сохранённые встречи

В первой версии все вошедшие пользователи относятся к одному пространству ВолГУ
Проверки принадлежности к вузу пока нет — подтверждение email не является подтверждением статуса студента
Чужие профили целиком, email, закладки и списки участия недоступны
В карточке встречи публикуются имя организатора, факультет и курс

Создание приглашения и изменения участия выполняются через функции базы
Пользователь не может передать чужой `user_id`, назначить себя администратором или обойти проверку вместимости прямой записью в таблицу
Организатор занимает одно место автоматически
`unicore_set_joined` блокирует строку встречи на время проверки и записи, а повторный запрос с тем же желаемым состоянием не создаёт дубль
`unicore_snapshot` возвращает согласованный снимок данных и количество участников

Приложение обновляет данные раз в 15 секунд в активном состоянии, при возврате из фона и по жесту pull-to-refresh
Это опрос сервера, WebSocket Realtime пока не используется
Автоматически миграции не добавляют пользователей и события
Для наполнения тестового проекта есть отдельный [сидер](seeds/README.md) с командами `npm run seed:preview` и `npm run seed`
Новые события `kind=event` создаются пользователями через приложение
Снимок загружает все встречи первого кампуса, перед большим запуском нужны пагинация и лимиты

## Проверки

```powershell
# в корне репозитория
npm run check

cd apps\mobile
$env:PLAYWRIGHT_CHROME_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'
npx playwright test --config playwright.backend.config.ts
npm run test:e2e
```

`tests/database.test.ts` в корне репозитория выполняет настоящую SQL-миграцию в локальном PostgreSQL-движке PGlite
Проверяются права двух/трёх пользователей, закрытый доступ без входа, лимит мест, повторные запросы, приватность и валидация
Тестовая схема `auth` имитирует JWT-контекст Supabase, не заменяя проверку реального Auth в облаке
`apps/mobile/tests/backend-e2e` проверяет браузерный UI и контракты HTTP с подменёнными ответами, не создаёт облачные аккаунты и не отправляет письма
Полный облачный сценарий проверяется двумя реальными тестовыми аккаунтами: создание, присоединение, отмена, обновление и повторный вход

## Соорганизаторы

После трёх миграций от 12 ноября выполните только `202611200001_event_rooms.sql` в SQL Editor — это одна транзакция для чата, соорганизаторов и партнёров
Организатор назначает и снимает помощников в разделе «Список участников и чат» своей встречи
Помощнику доступны состав встречи, общий чат и исключение обычных участников
Снятие роли сохраняет запись на встречу, отмена записи удаляет роль

## Первый администратор и партнёры

Справочник сохраняет стартовые пары проекта и включает обозначения групп из опубликованных материалов ВолГУ. Это не полный реестр на текущий семестр. Источники: [институты ВолГУ](https://volsu.ru/struct/institutes/), [ФТИ](https://www.volsu.ru/struct/institutes/fti/schedule/), [ИМИТ](https://volsu.ru/struct/institutes/mathematicandit/fmit_raspisanie/), [ИЕН](https://volsu.ru/struct/institutes/ien/biology/vneuchebnaya-rabota.php), [ИИМОСТ](https://volsu.ru/struct/institutes/iimost/new-section/), [институт права](https://volsu.ru/struct/institutes/philsocandlaw/novoe-raspisanie/)

В Authentication → Users скопируйте UUID своего существующего аккаунта. В SQL Editor замените заполнитель своим UUID и выполните:

```sql
insert into public.unicore_admins(user_id)
values ('ВАШ-UUID'::uuid) on conflict do nothing;
```

Обновите профиль в приложении → «Пригласить партнёра» → «Создать промокод». Передайте код представителю компании: «Партнёр» → «Создать аккаунт». Код одноразовый, срок действия 7 дней, для следующих входов нужны только почта и пароль

Чтобы отозвать права администратора, удалите его строку из `public.unicore_admins` через SQL Editor. Приложение не может самостоятельно выдать эти права

## Автономный режим

Для работы без сети явно установить `EXPO_PUBLIC_DATA_MODE=mock` и перезапустить Expo
При ошибках сервера приложение не переключается на моки автоматически
Старые локальные профили и встречи не переносятся в облако автоматически
